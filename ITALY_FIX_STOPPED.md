## B. VERIFIED PAYMENT-STORE DESIGN

Three different payment implementations coexist:

### Thailand (reference implementation)
- **Class/module**: `SQLiteInvoiceStore` from `/opt/xrplme/thoughts/api/sqlite_invoice_store.py`
- **DB path**: `/home/xrpladmin/xrplme-state/x402.sqlite3` (745KB, 1,429 invoices)
- **Initialization**: `payment_store = SQLiteInvoiceStore()` — called at module load
- **Invoice creation**: `invoice_id = secrets.token_hex(16)` → 32-char hex (auto-generated by SQLiteInvoiceStore)
- **Invoice TTL**: `invoice_ttl_seconds = 600` (explicitly set)
- **Payment verification**: Full x402 v2 middleware (`require_x402` with `invoice_store=payment_store`)
- **Replay protection**: `used_tx_registry` table (130 entries), `payment_proof_digest` via HMAC-SHA256
- **Restart persistence**: YES — invoices survive restarts
- **x402_xrpl default**: When `invoice_store` is NOT passed to `RequireX402Options`, the library uses `_InMemoryInvoiceStore()` (a dict — completely ephemeral)

### Macau (new template, standard x402 v2)
- **Class/module**: `SQLiteInvoiceStore` — same as Thailand
- **DB path**: Same shared `/home/xrpladmin/xrplme-state/x402.sqlite3`
- **Initialization**: `payment_store = SQLiteInvoiceStore()` at module load
- **Invoice creation**: 32-char hex via `secrets.token_hex(16)`
- **Invoice TTL**: Default 900 seconds (not explicitly set)
- **Payment verification**: Same x402 v2 middleware pattern
- **Replay protection**: Same SQLite-based approach
- **Restart persistence**: YES

### Brunei (uses x402_xrpl but NOT SQLiteInvoiceStore — 12 other countries same)
- **Class/module**: No `invoice_store` passed → x402_xrpl uses `_InMemoryInvoiceStore()`
- **DB path**: None — in-memory dict
- **Initialization**: `RequireX402Options(...)` WITHOUT `invoice_store=payment_store`
- **Invoice creation**: x402_xrpl library auto-generates invoice_id (format varies by library defaults)
- **Invoice TTL**: Default 900 seconds
- **Replay protection**: In-memory only — lost on restart
- **Restart persistence**: NO — invoices lost on restart

Countries using in-memory store (no SQLiteInvoiceStore): au, ch, de, fr, hongkong, brunei, laos, myanmar, timor-leste, papua-new-guinea, ph, sg

### Italy (fully custom implementation)
- **Class/module**: Custom `get_invoice_id()` function
- **DB path**: None — not logged anywhere
- **Invoice creation**: `sha256(os.urandom(32)).hexdigest()[:12].upper()` → 12-char hex
- **Invoice TTL**: None — invoice expires when process restarts
- **Payment verification**: Custom `X-PAYMENT-SIGNATURE` header check (no facilitator verification)
- **Replay protection**: None — invoice_id is only stored in the local variable
- **Restart persistence**: NO
- **x402 compliance**: NONE — does not use x402_xrpl library, does not generate x402 v2 responses

### Italy's intended target — the canonical pattern:
Italy will use the **standard x402 v2 pattern** with `SQLiteInvoiceStore` (same as Thailand and Macau), providing:
- 32-char hex invoiceId (via `secrets.token_hex(16)`)
- x402Version: 2, scheme: "exact"
- sourceTag: 804681468
- `payment-required` base64 header
- Persistent invoice logging in `x402.sqlite3`
- HMAC-based proof digests for replay protection

**Important distinction**: Italy will use the canonical `SQLiteInvoiceStore` pattern (same as Thailand and Macau). It will NOT use the in-memory store pattern that 12 other countries use. This is acceptable — invoice store standardization is a separate future task (not part of this bite).
